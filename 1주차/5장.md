## 표현식과 문

### 값

- 값은 식이 평가되어 생성된 결과를 말한다.
- 평가란 식을 해석해서 값을 생성하거나 참조하는 것을 의미한다.

### 리터럴

- 리터럴은 사람이 이해할 수 있는 문자 또는 약속된 기호를 사용해 값을 생성해 값을 생성하는 표기법을 말한다.

### 표현식

- 표현식은 값으로 평가될 수 있는 문이다. 즉, 표현식이 평가되면 새로운 값을 생성하거나 기존 값을 참조한다.

### 문

- 문은 프로그램을 구성하는 기본 단위이자 최소 실행 단위다. 문의 집합으로 이뤄진 것이 바로 프로그램이며, 문을 작성하고 순서에 맞게 나열하는 것이 프로그래밍이다.

### 표현식인 문과 표현식이 아닌 문

- 변수 선언문은 값으로 평가될 수 없으므로 표현식이 아니다.
- 표현식인지 아닌지는 변수에 할당해보면 알 수 있다.

### 정리 및 질문

<details>
<summary><strong>리터럴과 생성자 함수로 객체를 만드는 방식 차이는 무엇인가요?</strong></summary>

> 리터럴과 생성자 함수로 객체를 만드는 방식의 차이는 객체 생성 목적과 재사용성에 있습니다. 객체 리터럴은 {} 를 사용해 하나의 객체를 직접 만드는 가장 간단한 방법으로, 단일 객체를 빠르게 생성할 때 적합합니다. 반면 생성자 함수는 같은 구조의 객체를 여러 개 만들어야 할 때 사용하며, new 키워드를 통해 공통 속성과 메서드를 가진 객체를 반복적으로 생성할 수 있습니다. 즉, 리터럴은 개별 객체 생성에 적합하고, 생성자 함수는 객체의 틀(설계도)을 만들어 재사용하는 방식입니다.

</details>

<summary><strong>return 줄바꿈 이슈를 설명해주세요.</strong></summary>

> return 줄바꿈 이슈는 자바스크립트의 세미콜론 자동 삽입(ASI) 때문에 발생합니다. return 뒤에서 줄바꿈이 되면 자바스크립트 엔진은 return; 으로 해석하여 그 아래 값은 반환되지 않습니다. 그래서 개발자는 객체나 값을 반환하려 했지만 실제로는 undefined 가 반환될 수 있습니다.

</details>

<details>
<summary><strong>콘솔 출력 값과 실제 반환 값은 같은 개념인가요?</strong></summary>

> 콘솔 출력 값과 실제 반환 값은 같은 개념이 아닙니다. 콘솔 출력 값은 console.log() 등을 통해 개발자가 화면에서 확인하도록 보여주는 값이고, 실제 반환 값은 함수가 return 을 통해 호출한 곳으로 돌려주는 값입니다. 콘솔 출력은 단순히 확인용이며 프로그램 흐름에 직접 전달되지 않지만, 반환 값은 변수에 저장하거나 다른 함수의 입력값으로 사용하는 등 실제 로직에 사용됩니다. 예를 들어 console.log(10) 은 화면에 10을 출력하지만 반환 값은 undefined 이고, return 10 은 출력은 없지만 함수 호출 결과로 10을 전달합니다.

</details>
