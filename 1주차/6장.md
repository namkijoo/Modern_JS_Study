## 데이터 타입

### 숫자 타입

- 숫자 타입의 값은 배정밀도 64비트 부동소수점 형식을 따른다.
- 숫자타입은 추가적으로 양의 무한대, 음의 무한대, NaN타입도 표현할 수 있다.

### 문자열 타입

- 문자열은 0개 이상의 16비트 유니코드 문자의 집합으로 전 세계 대부분의 문자를 표현할 수 있다.
- 자바스크립트에서 가장 일반적인 표기법은 작은 따옴표를 사용하는 것이다.

### 템플릿 리터럴

- 템플릿 리터럴은 런타임에 일반 문자열로 변환되어 처리된다.
- 템플릿 리터럴은 따옴표 대신 백틱을 사용해 표현한다.
- 템플릿 리터럴은 개행문자를 허용한다.

```javascript
var template = `Template literal`;
console.log(template);
```

### 불리언 타입

- 불리언 타입은 true, false 뿐이다.

### undefined 타입

- var로 선언하면 undefined로 초기화 된다.
- 개발자가 값이 없다는 것을 표현할 때는 null을 사용한다.

### null

- 의도적으로 값이 없다는 것을 명시한 값이다.

### 심벌 타입

- ES6에서 추가된 값으로, 객체의 유일한 프로퍼티 키를 만들기 위해 사용한다.

```javascript
# 이름이 충동할 위험이 없는 유일무이한 값인 심벌을 프로퍼티 값으로 사용한다.
var key = Symbol('key')

var obj = {}
obj[key] = 'value'
console.log(obj[key])
```

### 동적 타이핑

- 자바스크립트의 변수는 선언이 아닌 할당에 의해 타입이 결정 된다. 그리고 재할당에 의해 변수의 타입은 언제든지 동적으로 변할 수 있다. 이러한 특징을 동적 타이핑이라하며, 자바스크립트를 정적 타입 언어와 구별하기 위해 동적 타입 언어라 한다.

> Symbol이 도입되기 전에는 충돌을 피하기 위해 긴 문자열 키나 접두사를 사용했고, private 데이터는 클로저나 관례적인 \_private 네이밍으로 관리했습니다. 하지만 이런 방식은 충돌 가능성과 은닉 한계가 있었습니다. Symbol은 고유한 값으로 이러한 문제를 공식적으로 해결하기 위해 도입되었습니다.

<details>
<summary><strong>자바스크립트 엔진은 왜 데이터 타입을 알아야 하나요?</strong></summary>

> 자바스크립트 엔진이 데이터 타입을 알아야 하는 이유는 값을 저장하고 처리하고 해석하기 위해서입니다. 데이터 타입에 따라 필요한 메모리 크기가 달라지고, 같은 비트 값이라도 숫자로 볼지 문자열로 볼지 해석 방식이 달라집니다. 또한 덧셈, 비교, 타입 변환 같은 연산도 타입에 따라 결과가 달라지므로, 엔진은 올바른 실행을 위해 값의 데이터 타입을 반드시 알아야 합니다.

</details>

<details>
<summary><strong>Truthy / Falsy 란 무엇이고 객체는 왜 항상 truthy인가요?</strong></summary>

> Truthy / Falsy는 조건문이나 논리 연산식에서 불리언 값으로 평가될 때 true처럼 동작하는 값과 false처럼 동작하는 값을 의미합니다. 자바스크립트는 꼭 true, false가 아니어도 조건식에서 값을 자동으로 불리언으로 변환합니다. 대표적인 falsy 값은 false, 0, -0, 0n, "", null, undefined, NaN 이고, 이 외 대부분의 값은 truthy입니다.

객체가 항상 truthy인 이유는 객체는 값이 존재하는 참조 타입 데이터이며, 빈 객체 {} 나 빈 배열 [] 도 하나의 객체로서 메모리에 생성된 유효한 값이기 때문입니다. 즉, 내용이 비어 있어도 “존재하는 객체”이므로 조건문에서 true로 평가됩니다.

</details>
