## 타입 변환과 단축 평가

### 타입 변환

개발자가 의도적으로 값이 타입을 변환하는 것을 명시적 타입 변환 또는 타입 캐스팅이라 한다.
개발자의 의도와는 상관없이 암묵적으로 타입이 자동 변환 되는 것을 암묵적 타입변환 또는 타입 강제 변환이라 한다.

### 문자열 타입으로 변환(암묵적)

```javascript
1 + "2"; //"12" +연산에서 피연산자 중 한개가 문자열이기 때문에 문자열로 이어진다.

("`1+1 = ${1+1}`"); //"1+1=2 표현식의 평가 결과를 문자여ㅕㅕㄹ 타입으로 암묵적 타입 변환한다.
```

### 숫자 타입으로 변환(암묵적)

```javascript
1 - "1"; // 0
1 * "10"; //10
1 / "one"; //NaN
```

### 불리언 타입으로 변환(암묵적)

```javascript
1 - "1"; // 0
1 * "10"; //10
1 / "one"; //NaN
```

### 문자열 타입으로 변환(명시적)

- string 생성자 함수를 new 연산자 없이 호출하는 방법
- object.prototype.toString 메서드를 사용하는 방법
- 문자열 연결 연산자를 이용하는 방법

### 숫자 타입으로 변환(명시적)

- Number 생성자 함수를 new 연산자 없이 호출하는 방법
- parseInt,parseFloat 함수를 사용하는 방법(문자열만 숫자 타입으로 변환 가능)
- '+ 단항 산술 연산자를 이용하는 방법'
- '\* 산술 연산자를 이용하는 방법'

### 불리언 타입으로 변환 (명시적)

- Boolean 생성자 함수를 new 연산자 없이 호출하는 방법
- ! 부정 논리 연산자를 두 번 사용하는 방법

### 단축 평가

```javascript
"Cat" && "Dog"; // Cat은 truthy 값이고 논리 연산의 결과를 결정하는 두 번째 피연산자인 뒤에 dog을 반환한다
"Cat" || "Dog";
```

### 정리 및 질문

<details> <summary><strong>동적 타이핑과 타입 변환은 어떤 관계가 있나요?</strong></summary>

> 자바스크립트는 동적 타입 언어이기 때문에 변수에 저장되는 값의 타입이 실행 중 자유롭게 바뀔 수 있습니다. 이 과정에서 연산, 비교, 조건문 실행 시 값의 타입을 상황에 맞게 자동으로 변환하는 타입 변환이 자주 발생합니다. 즉, 동적 타이핑은 타입이 유연하게 바뀌는 특성이고, 타입 변환은 그 유연성을 실제 실행 과정에서 처리하는 방식입니다.

</details>

<details> <summary><strong>숫자를 문자열로 바꾸는 가장 안전한 방법은 무엇인가요?</strong></summary>

> 숫자를 문자열로 바꾸는 가장 안전한 방법은 String() 함수를 사용하는 것입니다. String(10) 처럼 사용하면 명확하게 문자열로 변환할 수 있고, 다양한 값도 일관되게 처리할 수 있습니다. 반면 .toString() 은 null 이나 undefined 에서는 에러가 발생할 수 있어 주의가 필요합니다.

```javascript
String(10); // "10"
String(NaN); // "NaN"
```

</details>

---

<details> <summary><strong>Symbol() 을 문자열로 변환할 때 주의점은 무엇인가요?</strong></summary>

> Symbol 값은 일반 문자열 연결(+) 과정에서 자동으로 문자열 변환되지 않습니다. 따라서 Symbol() + "" 처럼 사용하면 TypeError가 발생합니다. 문자열로 변환하려면 반드시 String(symbol) 또는 symbol.toString() 을 사용해야 합니다.

```javascript
const sym = Symbol("id");

String(sym); // "Symbol(id)"
sym.toString(); // "Symbol(id)"
```

</details>

<details> <summary><strong>옵셔널 체이닝과 null 병합 연산자를 함께 쓰는 이유는 무엇인가요?</strong></summary>

> 옵셔널 체이닝(?.)은 객체가 null 또는 undefined 일 때도 에러 없이 안전하게 프로퍼티에 접근할 수 있게 해주고, null 병합 연산자(??)는 그 결과가 null 또는 undefined 일 경우 원하는 기본값을 설정할 수 있게 해줍니다. 즉, 하나는 안전한 접근을 담당하고 다른 하나는 기본값 처리를 담당하므로 함께 자주 사용됩니다.

```javascript
const username = user?.profile?.name ?? "Guest";

#위 코드는 user 나 profile 이 없어도 에러 없이 "Guest" 를 반환합니다.
```

</details>
